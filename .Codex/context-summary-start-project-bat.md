  - 模式：切换到脚本目录后启动服务，敏感配置只保存在当前进程环境中。
  - 可复用：启动脚本必须与调用时所在目录无关，并避免写入凭据。
  - 需注意：运行期间需要保留终端窗口。
- **实现 3**：`deploy/selfhost-entrypoint.sh`

  - 需注意：这是生产容器入口，本次批处理只负责 Windows 本地开发，不复制生产迁移流程。
- **实现 4**：`deploy/server-install.sh`
  - 模式：复用既有构建系统，并在缺少依赖或配置时停止。

### 2. 项目约定

- **命名约定**：npm 脚本和代码标识符使用英文；用户提示使用简体中文。
- **文件组织**：开发辅助入口放在项目根目录，领域服务脚本保留在各自目录。
- **代码风格**：批处理使用 `setlocal` 隔离环境，所有路径均加双引号，命令失败后检查 `errorlevel`。
- **编码**：文件使用 UTF-8 无 BOM，脚本启动时切换到代码页 65001。

### 3. 可复用组件清单

- `package.json` 中的 `dev`：启动 Vinext/Vite 开发服务。
- `package-lock.json`：通过 `npm ci` 可重复安装依赖。
- `vite.config.ts`：提供本地 D1、R2 和 Worker 绑定。

### 4. 测试策略

- **测试框架**：Node.js Test Runner，完整测试入口为 `npm test`。
- **脚本验证**：检查批处理前置校验分支，再实际启动服务并请求 `http://localhost:3000`。
- **覆盖要求**：正常启动、Node/npm 缺失提示、端口占用提示、依赖缺失时安装、启动失败保留错误信息。

### 5. 依赖和集成点

- **外部依赖**：Windows `cmd.exe`、Node.js `>=22.13.0`、npm。
- **内部依赖**：根目录 `package.json`、`package-lock.json`、`node_modules/.bin/vinext.cmd`。
- **集成方式**：批处理使用内置命令生成 Cloudflare `.dev.vars`，再调用 `npm run dev`；不启动 PowerShell 子进程。
- **配置来源**：已有 `.dev.vars` 优先；缺失时根据当前进程变量生成临时配置，并在服务退出后删除。

### 6. 技术选型理由

- **为什么用这个方案**：批处理适合 Windows 双击启动，同时保持 `package.json` 为开发命令的唯一事实来源。
- **优势**：不新增依赖、不写入凭据、错误信息直接可见、调用目录不影响运行。
- **劣势和风险**：固定使用本机端口 3000；端口已占用时必须先释放或调整脚本。

### 7. 关键风险点

- **并发问题**：重复双击可能争用 3000 端口，因此启动前显式检测。
- **边界条件**：Node 版本过低、npm 不可用、依赖安装失败、开发服务异常退出。
- **性能瓶颈**：首次执行 `npm ci` 需要下载依赖，后续不会重复安装。
- **安全考虑**：临时 `.dev.vars` 只包含本机回环服务的开发默认值，已被 `.gitignore` 排除，并在服务正常退出后删除；脚本不使用隐藏进程、下载命令或自动打开浏览器。
